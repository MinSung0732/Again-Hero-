# 제우스 초월 소환 컷신

## 현재 구현

확정·저장된 `reveal_entries`만 소비하는 5초 표시 계층이다. 일반/픽업 모두 기존 `award_shard_batch` 성공 이후 같은 `GachaRevealOverlay.present()` 경로를 사용한다. 확률0.5%, 픽업 풀 내부 가중치3, 골드100/1000, 첫 해금/반복 조각/프로필 사용권 및 내역 저장은 변경하지 않는다. 연출 파일에는 추첨·골드·보상 쓰기 호출이 없다.

실제 뽑기에서 `presentation_view`에 등록한 `src/ui/zeus_rig_cutscene_view.gd`를 재생한다. F6 리깅 미리보기도 같은 뷰를 사용한다.
- 0–0.4초: 어두운 신전·캐릭터 숨김.
- 0.4–1.35초: 실루엣 등장·보석 충전, 원본 색상은 아직 숨김.
- 1.35–2.45초: 위에서 아래로 본모습 공개,1.9초 지팡이에서 PNG 번개3방향 방출·짧은 섬광·배경 진동.
- 2.45–3.55초: 전신 유지, 충격파/입자 잦아듦·금빛 후광.
- 3.55–5초: 하단 native 이름 ‘제우스’ 등장·유지,5초 후 기존 획득 카드 복귀.

사용자768×1280 원본을 공유하는8본/8메시 연속 작은 움직임이며 파츠 PNG 재작화 모델은 아니다. 발 기준800/이름 시작850의540×960 세로 무대를 contain 배치하고 배경만cover한다. 루트/발·전신/지팡이 유지,nearest, 공개 셰이더로원본 색상/alpha보존.4프레임 PNG 번개는보석 Marker2D를 추종하고 균일회전/확대한다. 독립파츠/가려진부분 재작화와 큰스킬동작은여전히 추가원화가 필요하다.

플레이어가5초 monotonic 시계/스킵/취소를 관리한다. 뷰는루프/개발키입력 없이 set_time만 받는다. 등록된뷰를1회 생성해반복당첨에재사용하고1.9초 기존 Pixabay impact 효과음을 SFX로 재생·모든종료에서정지한다. 새몬스터는Catalog에 presentation_view를등록하거나기존generic계층을사용한다. 확률/보상저장 호출은추가하지 않는다. 화면방향은변경하지 않는다.

## 결과와 스킵

개별 결과를 획득 순서대로 공개하며 등록된 초월 결과 차례에만 컷신을 재생한다. 컷신 정상 종료와 자체 스킵은 그 결과의 기존 획득 카드로 연결한다. 카드 터치로 다음 획득을 진행한다. 제우스가 여러 번 나오면 각 순서에서 다시 재생한다. 기존 전체 스킵(`skip_to_results`)은 진행 중/로딩 중 컷신을 취소하고 한 번에 전체 결과 목록을 표시한다. generation/token 검사로 늦게 끝난 비동기 로딩과 오래된 종료가 결과를 덮지 않는다.

## 완료된 부분 / 임시 표현

완료: 실제일반/픽업/로컬테스트 연결, 결과순서/스킵/취소, 작은연속리깅·실루엣공개·PNG번개·하단이름, 캐시재사용·비율대응·같은코드의개발미리보기.

임시: 독립PNG파트/가려진몸통 재작화없음, 큰관절동작/가림교체는지원하지않는다. 구름독립애니메이션없음, 배경은기존가로신전을비율유지crop한다. 아래 리소스규격은향후원화교체용이다.

PNG 합성본은 캐릭터 슬롯에 넣지 않는다.

## 확률을 바꾸지 않는 미리보기

Godot 에디터에서 `src/dev/ZeusCutscenePreview.tscn`을 열고 F6 실행. 컷신만,1회 결과 연결,10+1회 중2/6/10번째 제우스3개 버튼을 제공한다. 모두 표시용 고정 결과, 실제 추첨/재화/계정 저장 없이 실행. 다시 뽑기는 구성하지 않아 비활성이다. PC 세로 미리보기:

```sh
godot --path . --resolution 540x960 res://src/dev/ZeusCutscenePreview.tscn
```

## 세로 전신 일러스트 제작용 최소 묶음 (2026-10-07)

세로 전체 화면 연출용 권장 규격이다. 기존 가로 무대 좌표는 해당 리소스를 연결할 때 세로로 재배치한다.

| 파일 | 권장 규격 | 내용 |
|---|---|---|
| temple_portrait.png | 1080×1920 PNG,1장 | 신전/구름 배경만; 중앙 인물 영역과 하단 이름 여백; 캐릭터/번개/글자 없음 |
| idle_01.png … idle_08.png | 각각768×1280 투명 PNG,6–8프레임 | 원본 비율 전신+지팡이; 같은 위치/크기; 머리·옷 끝만 작은 움직임;6–8fps loop |
| halo.png | 768×768 투명 PNG,1장 | 금빛 후광만; 기존 기하학 링 대체 선택 사항 |
| clouds_front.png | 1080×1920 투명 PNG,1장 | 독립 이동하는 구름만; 선택 사항 |

전신 프레임 공통 몸통 중심x384, 발바닥y1200 고정. 머리·장신구·지팡이까지 캔버스 안쪽 최소32px 여백. 프레임마다 얼굴/머리/체형/의상/장비 크기와 디자인을 유지하고, 마지막→첫 프레임이 이어져야 한다. 배경/번개/소환진/후광/글자를 캐릭터 PNG에 합성하지 않는다. 소환진과 번개는 기존 분리 PNG를 재사용할 수 있어 새 제작은 필수가 아니다. 이름은 게임 Label로 표시한다. manifest에는 셀 크기/프레임 순서/fps/loop/몸통 중심/발바닥 좌표를 포함한다.

5초 전체를150장의 캐릭터 프레임으로 만들 필요는 없다. 작은 idle loop를 캐릭터 공개 이후 반복하고, 밝기/실루엣 공개/번개/이름의 시간 변화는 게임 코드가 처리한다. 전신 정지 투명 PNG1장만 먼저 제공해도 세로 구도 연결은 가능하며, 실제 머리·옷 움직임은 프레임 확보 후 적용한다.

2026-10-07 최종1프레임 연결: 사용자 제공 원본768×1280 PNG 그대로 저장, 세로 무대/독립FX/이름 데이터 배치. 정지1프레임부터6–8프레임 동일캔버스로 확장하려면 character_count와 feet_y 배열을 함께 늘린다. 현재 파일명 idle_01.png, 추가파일 idle_02.png…08.png. 골드/확률/보상 저장 경로 변경 없음.
