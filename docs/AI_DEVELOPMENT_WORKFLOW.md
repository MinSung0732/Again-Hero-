# AI 개발 작업 기준

이 문서는 「용사, 또 너야? / Again, Hero?」를 수정하는 AI/코딩 에이전트의 공통 작업 기준이다. `AGENTS.md`와 함께 적용하며, 게임 설계의 최신 사실은 `PROJECT_CONTEXT.md`를 우선한다.

## 제품 방향

- 플레이어는 마왕으로서 몬스터를 소환하고, AI 용사는 자동전투·EXP·레벨업·증강 선택을 수행한다.
- 핵심 재미는 AI 빌드를 관찰하고 일부러 유도한 뒤 카운터 몬스터로 대응하는 과정이다.
- AI는 완벽 최적화가 아니라 최근 관측, 현재 몬스터 구성, 기존 빌드 관성, 용사 성향, 작은 랜덤성을 조합한 설명 가능한 판단을 한다.
- 기존 게임플레이 의미를 유지하며 확장한다. 핵심 재미 검증보다 시스템·콘텐츠 양을 먼저 크게 늘리지 않는다.

## 구현 원칙

- Godot 4.x와 GDScript, Android 우선 세로형 모바일 환경을 기준으로 한다.
- 콘텐츠 이름, 역할, 비용, 스탯, AI 가중치, 최대 레벨은 Catalog/Data에 둔다. 새 콘텐츠 ID를 여러 런타임 파일의 `match`/`if`에 반복하지 않는다.
- 새 콘텐츠 하나 때문에 무관한 여러 시스템을 함께 고쳐야 한다면 데이터 구조 분리를 먼저 검토한다. 반복 가능성이 낮은 규칙까지 과도하게 추상화하지 않는다.
- 전투 핫패스에서 전체 그룹 스캔, 매 프레임 임시 배열/Dictionary 생성, 반복 instantiate/free, O(n²) 탐색을 피한다.
- 반복 개체와 조회는 캐시, 풀링, 명시적 레지스트리, 공간 그리드, 프레임 분산 처리를 우선한다. 캐시는 생명주기와 무효화 조건을 명확히 한다.
- 비주얼·오디오 로딩 실패가 핵심 전투 스크립트의 초기화와 AI를 막지 않도록 가능한 경우 fail-soft 경로를 유지한다.

## 작업 순서

1. `AGENTS.md`, `PROJECT_CONTEXT.md`, `README.md`, `docs/ROADMAP.md`, `CHANGELOG.md`, 이 문서를 읽는다.
2. `git status`, 로컬 `HEAD`, `origin/main` 최신 SHA를 확인한다. 원격이 앞서면 사용자 변경을 침범하지 않는지 확인한 뒤 fast-forward만 사용한다.
3. 관련 Catalog, 씬, 스크립트와 호출 경로를 먼저 조사한다. 사용자가 `진행` 또는 `해줘`라고 한 경우 구현 방향을 바꿀 필수 선택이 없는 한 바로 작업한다.
4. 가장 작은 변경으로 기능을 완성하고 기존 게임플레이 의미와 데이터 중심 구조를 유지한다.
5. 기능 추가·패치·개선·제거·밸런스 변경은 `CHANGELOG.md` 최상단에 기록한다. 핵심 설계 결정이 달라지면 `PROJECT_CONTEXT.md`도 갱신한다.
6. `git diff --check`와 변경 범위에 맞는 정적 검증을 수행한다. 가능하면 Godot의 headless parse/import 검사도 실행하되, 실제 게임 실행과 구분해 보고한다.
7. 의도한 파일만 커밋하고 커밋 해시, 검증 결과, 실제로 실행하지 못한 검증을 짧게 보고한다.

## 오디오 작업

- 새 효과음이 필요하면 Pixabay에서 목적에 맞는 후보를 먼저 빠르게 찾는다. 검색은 소수 후보로 시간 제한을 두고, 다운로드나 접근이 지연되면 오래 붙잡지 말고 현재 장애를 보고한다.
- 라이선스와 사용 조건을 확인하고 출처 URL, 제작자, 파일/콘텐츠 ID를 `CHANGELOG.md` 또는 관련 출처 문서에 남긴다.
- Base64가 필요한 경우 다운로드/전달 수단으로만 사용한다. 한 번 디코딩해 `assets/audio/`의 실제 바이너리 파일로 저장하고 Godot 리소스가 그 파일을 참조하게 한다. 런타임 Base64 디코딩이나 PCM 합성 경로는 만들지 않는다.
- 재생 경로, 음량, import 상태를 정적으로 확인한다. 실제 청취나 게임 실행을 하지 않았다면 청감·런타임 검증 완료라고 하지 않는다.
