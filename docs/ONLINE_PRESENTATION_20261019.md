# 온라인 PNG·애니메이션·공통 공격 표현

## 병합과 기준

- 사용자 요청으로 main `6f22053f462e1176ec2ecde131d589d5491791b2`가 작업 브랜치 `4e7d1ccc215dee377368bbdd7517d74802a8ef7e`의 조상임을 확인하고 fast-forward했다. 충돌·별도 병합 커밋·강제 덮어쓰기 없이 기존 패치 전체를 반영했다.
- 원격 main의 SHA를 재확인하고 로컬 main도 일치시킨 뒤 `feature/stage10-astra`로 복귀했다. 이 문서의 새 표현 변경은 작업 브랜치에만 추가한다.
- 사용자가 양쪽 연결 끊김 후 복귀 및 양쪽 부재 무효 처리를 실기 확인했다고 보고했다. 이번 새 PNG 표현의 실기 검증을 의미하지 않는다.

## 구조

- wire protocol **3**. 콘텐츠 룰 ID/180초/로스터5종/무보상 룰은 유지한다. 서버와 두 클라이언트를 함께 업데이트해야 한다.
- 서버는 원래 Hero/몬스터가 실제 재생 중인 Sprite2D/AnimatedSprite2D의 PNG·Atlas 영역·변환 행렬·앵커·좌우 반전·색/alpha·레이어를 기존10Hz snapshot에 담는다. 용사 크기 정규화와 몬스터별 크기를 새 표로 복제하지 않는다.
- Hero/활성 몬스터의 시각 하위 노드는 첫 관측 시만 WeakRef 목록으로 캐시하고, 몬스터가 레지스트리에서 퇴장하면 제거한다. 전체 그룹을 스캔하지 않는다. 레이어와 같은 레이어의 화면 Y로 표현 순서를 정렬한다. 마왕성 장식의 전체 깊이 규칙을 복제하는 기능은 아니다.
- 기존 무기 런타임의 공통 투사체, 지속 장판/원형 PNG, 연쇄 PNG 및 소유한 네이티브 풀의 스프라이트를 샘플링한다. 공통 연쇄 텍스처 폭32px/장판 텍스처 alpha0.75를 기존 렌더러와 공유 상수로 묶었으며 기존 값/나머지 무기 런타임은 동일하다.
- 기본 관통탄의 원본 PNG 우선 경로는 유지하면서 buffer 디코딩/공유 source metadata를 사용한다. 원본 RGBA·프레임/스케일/충돌/피해·오디오를 바꾸지 않고, 생성된 ImageTexture에서도 PNG 경로를 찾을 수 있게 한다. 이 경로의 Image.load 리소스 경고도 제거한다. export에서는 기존 imported Texture2D fallback을 유지한다.
- 클라이언트는 서버 시각 명령을 그리기만 한다. Hero/몬스터/충돌/피해 시뮬레이션 노드를 만들지 않는다. 원본 PNG, nearest filtering, 기존 Atlas crop과 변환 행렬을 사용한다. 패널 밖은 clip한다.

## 자원·성능 경계

- `online_presentation_catalog.gd`: snapshot당 최대128개 시각 명령, PNG 캐시512개, 경로 길이/수치/프레임 영역 검사. 캐릭터 몸체를 공격 표현보다 먼저 수집하므로 FX 포화 시 몸체가 우선된다. 명령은 `res://assets/art/` 아래 PNG만 허용하고 경로 역참조/외부 URL/스크립트를 거부한다.
- 새 PNG는 update_state에서 캐시를 확인한 후 비동기 요청한다. draw 경로에는 파일 읽기/이미지 디코딩이 없다. 실패한 PNG도 다시 요청하지 않고 기존 기본 표현을 사용한다. 로딩 완료 후 폴링을 멈춘다.
- 화면당 작은 root 로더1개가 WeakRef로 뷰를 관찰한다. 평소/로딩 완료 후에는 처리하지 않으며, 화면이 나가면 진행 중인 요청만 nonblocking으로 소비하고 자신도 제거한다. 이 처리가 없을 때 퇴장 중 ObjectDB 누수를 실제 재현했다. 앱 전체 종료 시에만 남은 요청의 정리를 기다릴 수 있다.
- 클라이언트의 새 매 프레임 배열/그룹 조회·게임플레이 객체 생성은 없다. 서버의 명령 배열/직렬화와 정렬은 기존 snapshot 주기10Hz에 한정한다. 실제 FPS/서버 수용량 개선을 측정한 것은 아니다.
- 실제 인구48 및 공통 투사체 전체 슬롯을 활성화한 대표 fixture snapshot은 **21,993 bytes**, 기존 최대98,304 bytes 안이었다. 모든 가능한 효과 조합의 최악 크기나 실제 WSS 대역폭 측정을 의미하지 않는다.
- 경기 재입장 시 이전 mirror 상태만 비운다. 같은 화면의 텍스처는 재사용하고, 화면 파괴 후 캐시 참조를 해제한다. 재접속 일시정지는 서버의 마지막 프레임 그대로 멈춘다.

## 검증

- Godot4.5.1 headless. 체크아웃의 원본 PNG232개(용사/몬스터5종·효과228 + 비동기 검사 회복 PNG4)를 fixture에 덮어써 오래된 투명 placeholder와 구분했다. PNG 파일 자체와 리소스 import 설정은 수정하지 않았다.
- 새 `online_presentation_smoke`: 실제 룰5종 생성, Hero 공격 프레임/반전/정규화/앵커, 몬스터 몸체·레이어, Atlas 영역, 텍스처 재사용, 비동기 miss/완료·퇴장 drain, 입력 경로/NaN/목록 상한 거부, 장판/연쇄/풀링 관통탄 PNG·원본 관통탄 RGBA, 인구/투사체 포화·패킷 한도·몸체 우선, 퇴장 캐시/재입장 초기화 **155검사**.
- 기존 UI51 + 로스터 소환35 + 실제 온라인 전투44 + 버튼/거미/복귀48 + 자동 재접속66 + 라이프사이클53 + transport18을 함께 확인한다.
- 별도 서버/용사/마왕3프로세스에서 양쪽 상태30회·같은 경기/승자 PASS. 이는 loopback이며 WSS/실제 다른 기기 검증이 아니다.
- 실제 Windows4.7.2/Android 화면·원본 전체 마왕성/장식, GPU/FPS·native export·실제 네트워크 보간·신규 사운드 연결은 미검증/후속이다. headless는 실제 픽셀 출력의 시각 검수가 아니다.
- 이 단계는 모든 VFX 동기화 완료가 아니다. 적 투사체와 일부 커스텀 draw 절차 도형/궤도·특수 공격, 사망 잔상, 배경/장식은 후속 어댑터가 필요하다. 서버 전투/증강/판정은 기존대로 실행된다.

## 실기 적용

최신 작업 브랜치로 서버와 두 게임 모두 갱신 → 기존 서버 프로세스 종료·재실행 → 새 localtest 코드로 매칭한다. 용사/몬스터가 이동·공격 때 프레임/방향을 바꾸는지, 오크 등의 상대 체급과 관통탄·연쇄·장판 PNG가 맞는지 확인한다. 양쪽 끊기/복귀·무효·이탈/재매칭도 한 번 확인한다. 버전3 서버와 이전 클라이언트는 의도적으로 version_mismatch로 차단한다.

재현할 때 `tools/build_online_fixture.py`의 `--art-directory`를 반복해 체크아웃한 PNG 폴더를 지정한다. 기존 fixture를 재사용해도 해당 폴더의 PNG/import를 덮어쓰므로 이전 placeholder가 검증에 섞이지 않는다. 최소 폴더는 Hero/로스터5종 frames, 현재 Hero 무기 effect_dir들, `assets/art/heroes/item/heal_frames`다. 그 뒤 Godot editor import 및 위 테스트를 실행한다. 원본 아트의 체크아웃 여부/경로는 현재 Catalog/씬을 따른다.


최종 결과: 시각155 + UI51 + 로스터35 + 전투44 + 버튼48 + 복귀66 + 라이프사이클53 + transport18 = **570검사 PASS**. 최종 import ERROR/WARNING0, 실행 ERROR0. fixture 누락 아트 경고 각각43/0/43/82/43/199/121/43이며 미검수 아트를 숨기지 않았다. PNG byte 비교·무기 런타임의 나머지 코드 동일 확인·Python AST/git diff --check 통과. 로딩 중 퇴장 probe는 수정 전 ObjectDB 경고를 재현했고 수정 후 오류/누수 경고0이었다.
