# 모바일 첫 전투 90% 종료 대응 — 2026-10-15

## 확인한 경로

90%는 PackedScene 읽기가 끝난 뒤 새 씬의 `_ready()`와 `prepare_presentation()`을 실행하는 구간이다. Android 크래시/LMK/logcat 로그와 실제 기기는 확보하지 못했으므로 종료 원인을 OOM으로 확정하지 않는다. 다음 과도한 메모리 중첩은 소스에서 확인되어 수정했다.

- Battle은 사용 여부와 관계없이 카탈로그 46종을 모두 임시 생성하고 일반/엘리트 프레임과 부수 효과를 정적 캐시에 남겼다.
- 마왕 Main의 소환 연출 설치는 등록된 초월 6종의 화면/월드 효과/사운드를 장착 여부와 관계없이 준비했다.
- 기존 로비가 살아 있는 동안 다음 전투의 씬과 이미지 로딩을 병행했다.
- Hero 텍스처 로더는 원본 PNG가 함께 배포되면 imported resource보다 먼저 새 ImageTexture를 만들어 같은 파일을 재사용하지 못했다.

## 변경

1. 두 솔로 전투 경로로 전환할 때 영속 로딩 오버레이를 표시하고 이전 씬을 삭제한 뒤 두 프레임을 경유한다. 그 후 이전 목적지 이미지/크롭 캐시, MonsterVisual 프레임 캐시, 용사 무기 시퀀스 캐시를 비우고 새 PackedScene 및 이미지 요청을 시작한다. 살아 있는 노드가 보유한 리소스 참조는 파괴하지 않는다.
2. 마왕은 현재 편성 + 장착 초월, 용사는 해당 단계/난이도의 초기 로스터 + 허용된 예약 정예/대형/최종 보스만 준비한다. 300초 이후 신규 증원은 기존 실제 소환 경로에서 준비된다. 콘텐츠를 삭제하거나 전투 스탯·출현·보상을 바꾸지 않는다. 처음 등장하는 미리 준비하지 않은 배우는 첫 로딩 비용이 생길 수 있다.
3. 준비 완료 플래그는 앱 전체 정적 값에서 Battle 인스턴스 값으로 바꾼다. 재입장/다른 편성도 각자 준비한다. 온라인 룸은 기존처럼 솔로 준비를 건너뛴다.
4. 초월 연출은 장착한 1종만 준비한다. 미장착이면 0종. 명시적인 여러 종 프리뷰는 그대로 지원한다. 실제 용사 처치 강조/사망 연출/기존 캐시 재사용은 유지한다.
5. Hero는 warmup → ResourceLoader imported texture → 원본 PNG fallback 순으로 재사용한다. 오래된 import를 우회하기 위한 원본 우선 로딩은 제거했다. 에셋 교체 후에는 Godot에서 정상 재가져오기를 거쳐 내보낸다.
6. 모바일 Texture2D 동시 준비 요청은 4개에서 1개로 줄인다. 전투 중 프레임 처리/풀 크기/피해·속도·밸런스 변경은 없다.

전환 중에도 입력 차단/중복 요청 거절을 유지한다. 입장 옵션/스테미너 티켓은 SceneTransition이 보유해 이전 씬 삭제와 관계없이 목적지에서 한 번 소비한다. 읽기 실패 시 영속 로딩 화면의 기존 재시도 버튼을 유지한다. 변경은 Main/HeroMode 전환에 적용하며 로그인/로비의 기존 전환은 유지한다.
