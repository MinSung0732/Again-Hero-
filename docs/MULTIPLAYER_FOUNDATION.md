공통 원거리 AI의 방향/속도 결과를 재사용 intent 버퍼에 기록하고 이동/clamp/기본공격을 action port로 분리했다. 기존 status/skill/직업 분기와 무타깃 배회는 유지하며, 전체 용사 행동 분리가 완료된 것은 아니다. 독립 Godot4.5.1 before/after 6,255검사 통과, 변경 대상 외 실제 Hero609함수 동일 확인. [HERO_ACTION_PORT_FOUNDATION.md](HERO_ACTION_PORT_FOUNDATION.md)에 계약·검증·후속·롤백 기록. 전체 게임4.7/모바일은 미검증이고 용사 플레이·서버·PvP는 아직 비활성이다.

## 후속 진행 — entity ID/generation 첫 적용 (2026-10-10)

용사·battle 생성 몬스터·battle 풀 투사체에 epoch/slot/generation 레지스트리를 연결했다. 풀 재사용은 새 수명, 반납/사망/tree exit는 무효화한다. 새 battle Node에서도 이전 명령/handle이 겹치지 않게 로컬 router epoch를 프로세스 공용으로 증가시킨다. 기존 탐색/피해 instance ID와 전투 tick은 유지한다. 독립 Godot4.5.1 검증406검사 통과. 범위·비용·한계·롤백은 [ENTITY_ID_FOUNDATION.md](ENTITY_ID_FOUNDATION.md). 전체 게임4.7/모바일 미검증, 서버·용사 action port·동기화는 아직 미구현이다.

## 후속 진행 — 엘리트 선택 명령 경계 (2026-10-10)

엘리트/돌연변이 선택도 명령7과 독립 후보 revision에 연결했다. 기존 로컬 void API 유지, 표시 UI는 명시 revision 전달, 오래된 이벤트 선택은 거절한다. protocol v3. router130·증강79·엘리트 경계58검사 통과(독립 fixture, 실제 소환은 spy). 입력·시간 지도에 상세 기록. 다음 작업은 entity ID/generation 레지스트리 첫 적용이며 용사 action port/서버/동기화는 아직 미구현이다.

## 후속 진행 — 2단계 Run 시계 첫 분리 (2026-10-10)

증강 명령 경계 검증 통과 후 RunMetrics 경과 시간을 독립 BattleRunClock으로 분리했다. 기존 `_process` delta/실행 순서/RUN_TIMER pause gate는 유지한다. 전투 제한시간·기록·전략 분석·연구 보상의 기존/신규 비교 1,236검사 통과. 카탈로그 이름만 동일 spy를 사용한 독립 Godot4.5.1 검증이며 전체 게임4.7/모바일/성능은 미검증이다. [RUN_CLOCK_FOUNDATION.md](RUN_CLOCK_FOUNDATION.md)에 코드·검증·롤백 상세를 기록했다.

이는 2단계의 첫 작은 작업이다. 전체 고정 tick/액터 공통 시간/ID 레지스트리/상태 직렬화/서버 권한은 아직 미구현이며, 모든 단계 완료로 표시하지 않는다. 다음은 엘리트 선택 명령과 entity ID/generation 계약이며 전체 전투 회귀 전 온라인 모드를 활성화하지 않는다.

## 후속 진행 — 증강 명령 경계 (2026-10-10)

입력·시간 의존 지도는 [BATTLE_INPUT_TIME_AUDIT.md](BATTLE_INPUT_TIME_AUDIT.md)에 추가했다. 마왕 증강 선택/재뽑기를 명령 5/6으로 연결하고 protocol v2 choice_revision으로 재뽑기 전·이전 레벨 후보의 입력을 차단했다. 기존 public API 호출은 호환되며 main UI는 표시한 revision을 명시한다. router130검사·실제 경계/증강 함수 추출 fixture79검사 통과. 전체 전투/실기기는 미검증이다.

1단계는 6개 마왕 명령까지 완료했다. 엘리트 선택 및 용사 action port는 남아 있다. 검증을 통과하여 위 2단계 첫 작업인 RunMetrics 전투 시계 분리를 적용했다. 전체 고정 tick·액터 판정 분리는 아직 활성화하지 않는다.

## 1. 목표와 현재 완료 범위

기존 마왕 솔플의 전투·성장·연출을 유지하면서 동일한 전투 규칙에 용사 조작자와 서버 권한을 붙인다. 두 클라이언트가 독립적으로 계산한 전투를 억지로 일치시키기보다, 대전에서는 서버가 확정한 상태를 표시하도록 전환한다. 좌표를 보냈다는 이유만으로 피해·쿨타임·증강·보상이 동기화되는 것은 아니다.

이번 구현은 **1단계의 첫 작업: 마왕 입력 명령 경계**다. 실제 서버, 용사 플레이, PvP, 매칭은 아직 구현하지 않는다. 현재 솔플을 실행 가능한 상태로 두고 각 단계를 별도 커밋으로 검증한다.

| 항목 | 이번 상태 | 연결 위치 / 다음 작업 |
|---|---|---|
| 모드·역할·명령 ID | 구현 | `battle_session_catalog.gd`, 미래 모드는 실행 차단 |
| 소환·위치 소환·초월 소환·마왕 스킬 명령 | 구현 | 기존 `try_*` → router → 기존 실행 함수 |
| 버전·세션·역할·순서·유한 좌표 검사 | 구현 | 로컬 입력 경계, 네트워크 인증을 대신하지 않음 |
| 비용·쿨타임·인원·해금 검사 | 기존 유지 | battle 실행 함수가 계속 담당 |
| 중복·이전 전투 명령 차단 | 구현 | 실패한 게임 명령도 순서 번호 소비 |
| 진단 카운터 / 선택적 명령 처리 시간 | 구현 | 요청 시 조회, 기본 시간 측정 꺼짐 |
| 용사 이동·공격·스킬·증강 선택 명령 | 일반 이동/기본공격 포트 연결 | 전용 스킬·특수 이동·타깃 handle·플레이어 명령은 남음 |
| 고정 시뮬레이션 시계 / RNG 분리 | 미구현 | 시간 의존 목록을 조사한 뒤 순차 전환 |
| 서버 전투 / 스냅샷 / 재접속 / 랭크 보상 | 미구현 | 4~8단계 |

기준 코드와 공개 호출부를 확인했지만, 작업 환경은 전체 게임 리소스를 갖춘 체크아웃이 아니다. 전투 FPS·최초 입장 시간·모바일 메모리의 실제 기준값은 아직 측정하지 않았다. 이번 독립 테스트 통과를 전체 전투 실행 성공이나 성능 향상으로 해석하지 않는다.

## 2. 모드와 조작자 계약

| 모드 | 용사 조작자 | 마왕 조작자 | 규칙 확정 주체 | 활성화 조건 |
|---|---|---|---|---|
| DEMON_SOLO | 기존 관찰·성향·관성 기반 AI | 로컬 플레이어 | 로컬 전투 | 현재 지원 |
| HERO_SOLO | 로컬 플레이어 | AI 감독 / 소환 정책 | 로컬 전투 | 용사 조작·AI 마왕·진행 검증 |
| PVP_CASUAL | 원격 플레이어 | 원격 플레이어 | 전용 전투 서버 | 인증·두 클라이언트·재접속 검증 |
| PVP_RANKED | 원격 플레이어 | 원격 플레이어 | 전용 전투 서버 | 로드아웃·승패·보상 단일 확정 검증 |

역할은 스킬 권한이고 진영은 피아 판정이다. 모드·역할·진영을 하나의 boolean으로 합치지 않는다. 현재 원시 게임 데이터·밸런스는 공통으로 유지하며 대전 보정이 필요하면 명시적인 ruleset으로 적용한다. 로비/팀편성/계정 저장과 전투 세션은 서로 다른 생명주기를 갖는다.

목표 구성: `입력 UI / AI / 원격 입력 → CommandIngress → BattleSimulation → State / Events → 화면·음향`. 솔플은 로컬 실행 어댑터, 대전은 전송 어댑터를 선택한다. UI가 전송 구현이나 서버 주소를 직접 알아야 하는 구조를 만들지 않는다. 지금 거대한 프레임워크를 먼저 만들지 않고 명령별 실행부를 점진적으로 이 경계 안으로 옮긴다.

기존 용사 AI의 최근 관측·현재 몬스터 구성·빌드 관성·성향·랜덤성은 그대로 보존한다. AI와 플레이어는 공통 용사 액션 인터페이스를 호출하되 판단 정책은 공유하지 않는다. AI를 완벽 최적화 정책으로 바꾸는 작업은 이 계획에 포함하지 않는다.

## 3. 현재 명령 경계 상세

`battle_command.gd`는 엔진 네트워크와 무관한 작은 요청 객체다. 입력 때만 하나 생성하며 프레임마다 큐나 Dictionary를 만들지 않는다. `battle_command_router.gd`는 전투마다 하나 유지하고 세션 시작 때 카운터·역할·순서를 초기화한다.

| 필드 | 현재 의미 | 대전 전환 시 원칙 |
|---|---|---|
| protocol_version | 요청 구조 버전 1 | handshake 불일치 시 참가 거절 |
| session_id | 로컬 프로세스의 새 전투마다 증가하는 epoch | 서버 match ID + epoch 별도 지정 |
| actor_id | 신뢰된 로컬 슬롯 1 | 인증된 연결에서 서버가 슬롯 지정 |
| sequence | actor별 증가 순서 | 재전송 중복 처리 및 ACK 연결 |
| kind | 고정 숫자 ID 1~4 | ID 재사용 금지, 미지원 명령 거절 |
| subject_id | 몬스터 / 스킬 카탈로그 ID | 서버가 로드아웃·보유·해금 확인 |
| position | 수동 소환 좌표 | 유한 값 검사 후 기존 맵·거리 검증 |
| direction | 빈 값 또는 동서남북 | 입력 타입 검증, 효과 계산은 서버 |

현재 순서: 초기화 확인 → 지원 모드 → 버전·세션 → 슬롯·역할 → 명령·순서 → 인자 형식 → 순서 소비 → 기존 게임 검사·실행 → bool 반환. 마력이 부족했던 명령을 같은 번호로 다시 보내 마력이 회복된 뒤 실행할 수 없다. 형식/권한 오류는 실행부에 도달하지 않는다. 존재하는 카탈로그 ID인지와 비용 등은 기존 실행부에서 검사하여 규칙을 두 군데 작성하지 않는다.

현재 router는 동기 호출이다. 네트워크 지연, 명령 tick 배치, ACK, 인증, 속도 제한은 아직 없다. 일반적인 서버용 수신기를 이 로컬 클래스로 즉시 대체하지 않는다. 현재 sequence는 순서가 보장된 로컬 입력을 전제로 높은 번호 이후 낮은 번호를 거절한다. 미래 네트워크에서 순서 없는 입력을 받으려면 전용 수신 창·틱 버퍼 정책부터 구현한다.

public `try_summon`, `try_summon_at_position`, `try_summon_transcendent`, `try_use_demon_ultimate` 이름과 반환형은 유지했다. main UI의 호출 변경 없이 연결한다. 실행 본문은 `_execute_*`로 옮겼으며 기존 게임 신호·자원 차감·미션 집계는 유지한다. 초기화 전 호출은 거절한다.

`command_routing_enabled=false`는 현재 솔플에서만 기존 직접 실행으로 돌아가는 임시 회귀 비교/롤백 스위치다. 미래 모드 검사보다 앞에 놓으면 안 된다. 네트워크 모드가 들어오면 솔플 어댑터에 한정하거나 제거한다. 입력을 우회하는 디버그·자동 소환 경로는 이번 단계에 합치지 않았으며, 다음 단계에서 플레이어 의도와 서버 내부 이벤트를 구분하여 목록화한다.

`get_battle_command_diagnostics()`는 명시적 진단 조회용이다. HUD `_process`에 붙이지 않는다. `set_battle_command_profiling(true)`는 동기 실행 함수의 소요 시간만 측정하며 몬스터의 이후 프레임 처리·GPU·전체 로딩 시간은 포함하지 않는다.

## 4. 공유 전투 규칙과 시간 분리

2단계에서 몬스터·용사·투사체·상태이상·증강·전투 종료의 판정 주체를 조사한다. 순서: 상태 조회 인터페이스 → 시간 의존 분리 → 주체별 규칙 분리. battle.gd를 한 번에 통째로 재작성하지 않는다. 기존 캐시·풀·공간 그리드·레지스트리를 그대로 재사용한다.

전투 시간과 화면 시간을 구분한다. 전투 tick은 피해·쿨타임·소환·상태이상·AI 관측에 사용한다. 화면 delta는 카메라·HUD·보간·시각 연출에 사용한다. 일일미션·탐색보상은 벽시계/계정 시스템에 계속 남긴다. 기존 물리 업데이트 빈도를 먼저 측정하고 유지한 상태에서 이주한다. 새 30/60Hz를 측정 없이 전체 적용하지 않는다.

`Time.get_ticks_msec`, `create_timer`, await, `Engine.time_scale`, tween callback으로 실제 피해나 사망을 확정하는 곳을 목록화한다. 피해는 전투 시간의 예약 이벤트로, 애니메이션 완료는 표시 이벤트로 점진적 분리한다. 예약 항목에는 entity ID+generation을 넣고 대상 소멸/세션 변경 때 폐기한다. 한 tick 처리 개수·큐 용량은 상한을 둔다.

RNG는 규칙용과 연출용을 분리하고 전투 seed 및 rules revision을 기록한다. AI 판단·증강 후보·랜덤 장판은 규칙 RNG, 카메라 흔들림·파티클은 연출 RNG를 사용한다. seed와 고정 tick만으로 플랫폼별 물리 결과가 완전히 같아진다고 가정하지 않는다. PvP 결과는 서버 상태를 따른다.

## 5. 식별자·상태·이벤트 계약

네트워크에서는 `get_instance_id`, NodePath, 배열 위치를 영구 유닛 ID로 사용하지 않는다. 서버가 match 범위 entity ID를 발급하고 풀 재사용 시 generation을 증가시킨다. 오래된 이벤트는 generation이 다르면 폐기한다. 공간 쿼리는 기존 그리드, ID 조회는 Dictionary/레지스트리를 사용한다.

| 종류 | 예시 | 전송 / 보존 정책 |
|---|---|---|
| 입력 명령 | 소환, 용사 이동, 스킬, 증강 선택 | 검증된 intent, sequence/ACK, 제한된 재전송 |
| 상태 스냅샷 | 위치·방향·HP·보호막·쿨타임·상태이상·단계 | 최신 상태 위주, tick·기준 revision 명시 |
| 전투 이벤트 | 명중·폭발·사망·소환·증강 확정 | event ID 중복 제거, 필요한 것만 신뢰 전송 |
| 영속 결과 | 승패·등급 변화·보상 | 서버가 match ID별 단일 확정 및 트랜잭션 |

초기 스냅샷에는 살아 있는 entity와 남은 상태이상/장판 시간, 진행 중 선택, 규칙 seed/revision을 포함한다. 신규 참가/재접속에서는 전체 기준 스냅샷을 먼저 받는다. delta의 기준 revision을 잃었으면 전체 갱신을 요청한다. 네트워크 전송은 원시 타입과 제한된 배열/바이너리로 직렬화하며 Godot Object를 RPC 데이터로 전송하지 않는다.

상태이상 스택/갱신/면역 규칙, 슈텐 안개의 자해·보호·폭발, 만티코어 왕복 공격 등은 기존 의미를 그대로 직렬화 가능한 판정으로 옮긴다. 단순 위치·HP 동기화만 먼저 켜고 나머지를 클라이언트 독립 판정으로 방치하지 않는다.

## 6. 용사 모드 구현 설계

먼저 용사의 `HeroActionPort`를 정의한다: 이동 의도, 공격 의도, 대상 선택, 스킬 요청, 증강 선택 요청. 실제 범위·쿨타임·대상 생존 검사 및 실행은 공통 전투가 담당한다. 기존 AI는 이 포트의 입력 생산자, 플레이어 컨트롤러는 별도 입력 생산자로 만든다. 자동 기본공격 여부는 용사 모드 기획에서 확정하며 기존 AI 기본공격을 임의로 변경하지 않는다.

몬스터 자동전투는 공통으로 유지한다. AI 마왕은 소환 예산·카탈로그·해금·인원 제한을 같은 명령 경로로 사용한다. 모드 전용 난이도 정책을 기존 용사 AI 클래스 안에 섞지 않는다. 용사 보상·입장 조건·저장 슬롯·증강 선택 UI는 전투 액션 분리가 끝난 뒤 붙인다.

솔플은 증강 선택 중 기존 일시정지를 유지한다. 대전에서는 한 플레이어의 선택창/소환 컷신이 전체 서버를 정지시킬 수 없다. 선택 마감 tick, 미응답 시 기본 선택, 제시 후보와 선택 가능 여부를 서버가 관리한다. 후보 재뽑기·레벨업 중첩·선택 중 사망 정책은 일반전 시제품 이전에 확정한다.

## 7. 서버·전송·보정 설계

PC/모바일 네이티브 기준 초기 후보는 Godot headless 전용 전투 서버 + ENet다. Web export는 별도 전송 요구가 있으므로 같은 전송을 무조건 지원한다고 가정하지 않는다. 전송 코드는 어댑터로 두고 클라우드 저장과 분리한다. Supabase는 인증·친구·로드아웃·결과 저장에 사용하고, DB 행 업데이트로 매 프레임 좌표를 교환하는 설계를 피한다.

접속 순서: 계정 인증 → 매치 배정 → 짧은 수명의 서명된 입장 티켓 → 서버가 티켓·ruleset 확인 → actor/role 바인딩 → 기준 상태 수신 → 준비 완료 → 같은 시작 tick으로 전투. 티켓에 match ID·account ID·role·만료를 넣되 검증용 비밀키는 서버에만 둔다. 클라이언트가 보낸 actor/role은 권한 근거가 아니다.

서버는 이동 상한·맵 범위·소환 비용·쿨타임·인원·로드아웃·증강 후보·체력·승패를 직접 검증한다. 입력 속도·패킷 크기·명령 수·미래 tick 범위에 상한을 둔다. 잘못된 수치/알 수 없는 ID/만료 명령은 조기에 거절한다. 메모리 보호를 위해 명령 큐·이벤트 중복 캐시·재접속 기록은 match 범위와 용량/보존 시간으로 제한한다.

스냅샷 전송 10~20Hz는 측정 전 초기 실험 범위다. 판정 tick과 동일할 필요는 없다. 위치·방향은 여러 유닛을 묶어 전송하고 변화 없는 정보는 반복 전송하지 않는다. 중요한 확정 이벤트와 손실 가능한 최신 위치 스트림은 별도 채널 정책을 사용한다.

원격 유닛은 과거 스냅샷 사이를 보간한다. 로컬 용사 이동만 예측을 검토하며 서버 ACK 기준 입력을 재적용해 보정한다. 피해·자원 소비·증강·소환 성공은 서버 확정값을 따른다. 시각 효과의 선표시는 거절 시 취소 가능해야 한다. Godot 물리 보간과 네트워크 지터 버퍼/재조정은 다른 작업이다.

재접속은 actor를 새로 생성하지 않고 기존 서버 슬롯에 재바인딩하고 기준 스냅샷을 전송한다. 재접속 허용 시간·AI 대행·기권·무효 경기 정책은 일반전에서 데이터로 결정한다. 프로세스 죽음/서버 장애/양쪽 끊김도 결과 정책에 포함한다. 지연이나 연결 끊김만으로 클라이언트가 승리를 확정하지 않는다.

## 8. 계정·랭크·보상 안전성

현재 로컬 저장/클라우드 스냅샷은 솔플용으로 유지한다. 랭크 입장 때는 서버가 보유 몬스터·초월·연구·선택 가능한 로드아웃을 확인한다. 클라이언트가 올린 계정 스냅샷을 소유 증명으로 신뢰하지 않는다. 서버 검증 가능한 인벤토리·통화 원장으로 전환하는 별도 마이그레이션이 필요하다.

랭크 결과는 유일 match ID로 승패·등급·통계·보상 수령 상태를 원자적으로 확정한다. 중복 보고/재접속/요청 재시도에도 보상을 두 번 지급하지 않는다. 솔플 미션·탐색보상과 같은 wallet을 쓸 경우 기존 스냅샷 업로드가 확정된 서버 재화를 덮어쓰지 못하게 소유권·버전 규칙을 마련한다. 기존 저장 포맷을 이번 단계에서 바꾸지 않는다.

서비스 역할 키·서버 티켓 서명키·인증 토큰은 리포지토리나 게임 빌드에 포함하지 않는다. 결과 API는 서버 신원·match 참가자·확정 상태를 검증한다. 상세 에러/토큰을 클라이언트 로그에 남기지 않는다. DB 변경은 백업·호환 읽기·마이그레이션·복구 계획과 함께 별도 승인된 작업으로 진행한다.

## 9. 단계별 구현·통과 기준·롤백

| 단계 | 작업 단위 | 통과 기준 | 롤백 / 다음 단계 조건 |
|---|---|---|---|
| 0 기준 확보 | 최신 SHA, 호출부·시간·난수·그룹 검색 조사, PC/모바일 실측 | 첫/재입장, frame p95/p99, 메모리, 몬스터 수별 기록 | 소스 기준 확인 완료, 실측은 대기 |
| 1 명령 경계 | 이번 4개 마왕 명령, 다음 증강/재뽑기/용사 액션 | 기존 신호·결과·비용 동일, 중복/세션/권한 실패 테스트 | 이번 첫 작업 완료; 솔플 스위치 또는 커밋 revert |
| 2 공통 시뮬레이션 | 시계·RNG·entity ID·상태·예약 이벤트, 표시 분리 | 기존 전투 시나리오 회귀, 시간 중복 적용 없음, headless 규칙 실행 | 주체별 작은 커밋, 원래 주체로 복귀 |
| 3 용사 솔플 | action port, 플레이어 용사, AI 마왕, 증강 UI | 두 솔플 모드 해금·입장·성장·종료·보상 완주 | 모드 gate로 용사 모드 숨김, 마왕 솔플 유지 |
| 4 서버 시제품 | headless 1매치, 인증 전 로컬 테스트, 서버 입력 검증 | 두 로컬 클라이언트 동일 확정 HP/승패, 불법 명령 차단 | 오프라인 어댑터로 복귀, 운영 서버 미연결 |
| 5 동기화 | ID/generation, baseline/delta, 이벤트·ACK, 보간 | 유닛 풀 재사용/지연/손실/순서 변경/재접속 회귀 | 대전 gate 해제, 서버 프로토콜 버전 분리 |
| 6 일반전 | 티켓·역할 선택·매치 수명·끊김 정책 | 두 실기기 장시간 완주, 중복 액션/유령 유닛 없음 | 일반전 입장 중지, 기존 솔플 지속 |
| 7 랭크 | 서버 로드아웃·재화 원장·결과 단일 확정·등급 | 위조 로드아웃/중복 보상/서버 장애 테스트, 저장 덮어쓰기 차단 | 랭크 중지; 확정 재화는 코드 revert로 되돌리지 않음 |
| 8 부하·운영 | 동시 매치·지표·알림·재시작·버전 배포 | 정한 서버/모바일 예산 충족, 장애 복구 리허설 | 입장/동시 매치 제한, 이전 호환 서버 배포 |

1단계 남은 상세 작업: (1) 사용자 입력·AI 입력·서버 내부 발생 이벤트 호출 지도를 만든다. (2) 증강 선택/재뽑기를 후보 revision과 함께 명령화한다. (3) 용사 이동·공격·스킬 인터페이스를 기존 AI와 병행 도입한다. (4) 세션 구성은 실제 지원하는 controller 조합에만 연결한다. (5) 최신 전체 프로젝트에서 기존 마왕 솔플 회귀를 완료한 뒤 2단계로 간다.

2단계 분리 순서: (1) 규칙 시간 조회 wrapper, (2) entity registry ID/generation, (3) 상태이상 예약 처리, (4) 공격/투사체 판정, (5) 소환·증강·종료, (6) 표시 이벤트 sink, (7) 서버용 리소스 export. 모든 액터를 한 번에 바꾸지 않고 범용 몬스터 → 엘리트 → 초월 → 용사 순으로 회귀한다. 초월 특수 행동을 단순화하여 서버화하지 않는다.

## 10. 성능 검증과 운영 지표

최적화 수치는 실측 전 약속하지 않는다. 최소 비교 시나리오는 빈 전투, 평상시 전투, 유닛 50/100/200/300, 장판·투사체가 많은 초월 조합이다. 기존 개체 제한 밖 테스트는 전용 부하 fixture에서 수행한다. PC와 목표 모바일 저사양 기기에서 각각 최초 입장/재입장·시뮬레이션 CPU·메모리 peak·프레임 p95/p99를 기록한다.

서버화 이후 match별 tick 시간 p95/p99, backlog, 큐 길이, 초당 송수신 bytes, 스냅샷 크기, 명령 거절 사유, 보정 거리, 재접속 성공률을 측정한다. 서버 한 대당 매치 수는 이 데이터로 정한다. 네트워크 조건은 RTT 50/150/300ms, 손실 0/1/5%, 지터·중복·순서 역전·백그라운드/복귀로 검증한다. 이는 테스트 조건이며 지원 성능 보장은 아니다.

레지스트리·공간 그리드는 판정에서도 유지한다. 매 프레임 그룹 전체 검색이나 모든 쌍 비교를 네트워크 코드로 추가하지 않는다. 변한 entity를 재사용 가능한 목록에 기록하고 bounded 배치로 encode한다. 매 tick 전체 상태 deep-copy/JSON 생성, 유닛별 RPC 남발, 네트워크 이벤트마다 새 FX 생성/파괴를 피한다. 클라이언트에서 안 보이는 파티클·음향을 서버가 로드하지 않도록 서버 export 단계에서 분리한다.

## 11. 이번 검증 및 사용 방법

신규 모듈은 실제 Godot 4.5.1 headless 독립 fixture에서 검사한다. 저장소 전체는 Godot 4.7 설정이며 전체 리소스가 없는 환경이므로 전체 battle 장면 실행은 수행하지 않았다. 전체 프로젝트에서 아래 테스트를 실행할 때 자동 로드의 외부 접근 여부도 확인한다.

```bash
godot --headless --path . --script res://tests/battle_command_router_smoke.gd
```

테스트는 4개 명령 인자 전달, 방향·좌표 보존, 자원 실패 반환, 실패 후 재전송 차단, 중복/이전 순서, 세션 변경, 잘못된 역할·버전·좌표·명령, 미구현 모드, 중첩 신호 호출, 카운터 초기화를 검증한다. 이번 결과는 독립 명령 테스트 97검사 통과, 실제 public wrapper/dispatch를 추출하고 실행부만 spy로 대체한 임시 fixture 30검사 통과다. 경계 on/off 및 미래 모드 우회 차단을 확인했다. 별도로 기존 4개 실행 함수 본문과 수정 후 본문을 비교하여 이름 외 변경이 없음을 확인했다.

전체 프로젝트에서 다음을 수동 확인한다: 일반/수동/초월 소환, 마력 부족·인원 제한·해금 실패, 마왕 3개 포위 스킬 및 방향 선택, 미션 정상 집계, 증강/일시정지, 재입장, practice/tutorial. routing on/off를 각각 한 판 비교한다. 이것이 완료되기 전 온라인 모드를 표시하거나 서버 권한 기능이 완성됐다고 표기하지 않는다.

코드 롤백은 이 패치 커밋을 revert한다. 저장 schema·DB·기존 자원 값은 변경하지 않아 데이터 복구가 필요 없다. 후속 단계도 한 번에 main에 합치지 않고 검증한 묶음으로 진행한다.

## 12. 아침 검토 항목 / 다음 실행 우선순위

1. 최신 feature를 pull한 뒤 전체 Godot 프로젝트에서 import·스크립트 오류를 확인한다.
2. 위 마왕 솔플 회귀 체크를 수행하고 PC/모바일 최초·재입장과 전투 성능 기준값을 기록한다.
3. 다음 작업은 **1단계 나머지 입력 호출 지도와 증강 선택 명령화**다. 실제 용사 조작 방식이 확정되면 action port를 이어서 구현한다.
4. 일반전 시제품 이전에 용사 자동 기본공격, 선택 시간 제한, 접속 끊김/기권, 대전 밸런스 ruleset을 결정한다.
5. 실제 서버 배포 전 호스팅 지역·목표 동접·플랫폼·인증/재화 원장 이주를 검토한다. 지금은 이 선택 때문에 솔플 리팩토링을 중단하지 않는다.
