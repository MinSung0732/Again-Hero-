## 발견 및 수정

서버가 복귀 유예 만료 시 살아 있는 소켓과 좌석 deadline만으로 상대를 승자로 골랐다. 처음 매칭됐지만 `ready` 응답을 한 번도 보내지 않은 클라이언트도 이 조건에 들어갔다. 실제 입장코드 서버/두 WebSocket/실제 Battle을 사용하는 새 테스트에서 수정 전 오판정을 재현했다.

승리 후보에 기존 `peer.ready`를 추가해 준비를 완료한 연결된 상대만 승리한다. 준비 미완료 상태에서 상대 유예가 끝났고 준비된 상대가 없으면 기존 무효 결과(`both_disconnected`)를 사용한다. 이미 실행 중인 전투, 명시적 나가기, 복귀 유예15초/클라이언트 복구30초/결과 보관10초, wire protocol2와 인증/게임플레이/점수·보상은 유지한다. 새 수치/콘텐츠 예외나 배열·그룹 스캔을 추가하지 않는다.

## 검사 범위

`tests/online_lifecycle_smoke.gd`는 원래 서버/Client/Battle과 실행 시 생성한 입장코드를 사용한다. 고정 fixture 인증은 사용하지 않는다.

- 준비 전 한쪽 끊김 및 유예 만료: 미준비 생존 소켓의 부당 승리 방지, 양쪽 동일 무효 결과1회.
- 동일 세션으로 대기열 진입·취소3회: 남은 소켓/대기열/방/UID 예약 없음.
- 진행 중 양쪽 끊김 → 한쪽 복귀 시 정지 유지 → 두 번째 ready 후 같은 Battle 인스턴스 재개.
- 명시적 나가기 직후 클라이언트 노드를 제거해도 socket_drain이 leave를 전송하고 상대 승리1회.
- 같은 세션/UID로 즉시 재매칭: 이전 결과 보관 방과 새 방 공존, 이전 방 정리 후 새 방의 소켓·좌석·UID 예약·복귀 토큰 보존.
- 폐기한 이전 복귀 토큰 거부, 새 전투 무영향.
- 실제 Battle 시간 종료 및 중복 finish/result: 확정 승자·클라이언트 결과1회 유지.
- 마지막 대기열/방/예약/토큰 전부 정리.

만료 경계는 테스트에서 좌석 deadline/방 ended 시각만 과거로 옮겨 검사한다. 배포 상수는 바꾸지 않는다. 정상 연결은 실제 loopback WebSocket을 사용하지만, 물리 네트워크 지연/패킷 손실이나 여러 기기 환경을 재현한 것은 아니다. 표현 에셋은 기존 격리 fixture의 대체/누락 상태를 사용한다.

## 실기 확인 순서

1. 최신 코드를 받고 기존 서버 프로세스 종료 후 다시 실행한다. 새 서버 입장코드로 두 게임을 매칭한다.
2. 양쪽에서 연결 끊기 버튼을 누른 뒤, 유예가 끝나기 전에 한쪽만 재접속한다. 먼저 돌아온 쪽에서도 전투가 멈춰 있어야 한다. 나머지도 돌아오면 이어져야 한다.
3. 정상 연결 중 한쪽 로비 이탈: 상대 승리1회. 양쪽 다시 매칭해서 새 경기인지 확인한다.
4. 새 경기를 유지한 채 이전 결과 보관 시간10초 이상 기다린다. 새 경기가 종료되거나 끊기지 않는지 확인한다.
5. 대기열에서 취소 후 다시 입장해 정상 매칭되는지 확인한다. 양쪽 유예 만료는 무효이며 결과 보관 기간 안의 복귀는 확정 결과만 표시한다.

실제 Windows4.7.2/Android·Cloudflare WSS, OAuth 실계정, 전체 원본 아트/음원·GPU/FPS, 앱 강제종료/서버 재시작 복원은 이번 자동 검증 범위가 아니다.
