# 용사 모드 정지·소환 재개·문지기 슬롯 수정 — 2026-10-17

## 확인한 원인

기존 Battle은 지정된 그룹과 소환수 레지스트리의 `physics_process`만 껐다. 소환 애니메이션, 별도 `_process`, Tween/노드 Timer와 SceneTreeTimer를 기다리는 연속 공격은 계속 진행할 수 있었다. 재개 때는 원래 꺼져 있어야 하는 투사체의 물리 처리까지 켰다. 증강 UI도 실제 업그레이드를 적용하기 전에 전투를 재개했다.

기존 코드의 실제 Stage8 Battle/Hero/투견/사슬 투사체로 별도 재현했다. 정지 중 일반 process 진행, 소환 애니메이션 진행, 예약된 사슬 피해 진행, 3칸을 먼저 채운 뒤 배운 문지기의 소환 실패: 네 항목 모두 수정 전 실패, 수정 후 통과. 단일 소환수 API 호출만으로 영구 이동 정지는 재현되지 않았다. 따라서 영구 정지의 유일 원인을 단정하지 않고, 애니메이션·물리 처리 불일치와 재개 상태 덮어쓰기를 제거하고 실제 이동 재개를 검증했다.

## 동작 변경

| 대상 | 수정 후 |
| --- | --- |
| 용사 모드 모달 | Battle 소유 하위 트리 전체의 process mode를 중지하고 이전 모드를 복원한다. 새로 활성화한 개체도 정지 상태를 상속한다. |
| 소환수·투사체 | 개별 physics/process 플래그와 애니메이션 진행 상태를 보존한다. 비활성 풀 개체나 사슬의 잔여 공격 대기를 재개 때 강제로 켜지 않는다. |
| 증강 선택 | 전투를 멈춘 채 성장/기존 소환수 갱신을 적용한다. 누적 EXP가 다음 선택창을 열면 그 선택까지 끝난 뒤 재개한다. |
| 설정창 | 직접 열어도 정지 상태를 획득한다. 설정창만 닫으면 부모 일시정지 화면은 유지한다. |
| 지연 전투 기술 | Hero 14곳, 사슬 투사체 2곳의 지연은 `CombatDelay.wait`로 남은 시뮬레이션 시간을 소비한다. 화학 연속 발동·대마법 후속타·광전사 파동/회복/부활 등을 포함한다. 사망 페이드 0.52초는 종료 연출로 유지한다. |
| 절대 시각 상태 | 이동 둔화/속박/엘리트 가속의 설정·판독은 Battle의 정지 시간을 뺀 동일 시계를 사용한다. 정지 시간만큼 효과가 만료되는 경로도 제거한다. |
| 보스·지속 피해 | 기존 전투/시간 도메인 정지를 유지하고, 실제 DOT·보스 300초 경계의 정지를 검증한다. |
| 종료 연출 | 모달 중 전투 종료 시 하위 트리 모드를 복원한 뒤 전투 물리만 끈다. |

UI 입력, 증강 버튼의 0.25초 입력 방지, 전투 밖 화면은 계속 처리한다. 전역 SceneTree 정지는 사용하지 않는다. 마왕/온라인의 기존 정지 정책은 유지한다. 정상 모드의 지연과 절대 시각은 기존 SceneTreeTimer/시스템 시각으로 동작한다. 프레임별 전체 그룹 조회·임시 컨테이너/새 전투 노드는 추가하지 않는다.

## 소환 자리 정책

기존 고정 공유 3칸은 4종을 배웠을 때 마지막 종류가 영원히 못 나올 수 있었다. 기본 3칸을 유지하되 배운 소환 무기가 4종이면 최대 4칸으로 늘린다. 아직 나오지 않은 배운 종류의 자리를 예약하여 같은 종류의 반복 시전이 차지하지 못하게 한다. 이미 중복 개체가 기존 칸을 채운 뒤 새로운 종류를 배우면 그 중복 하나를 기존 풀로 돌려보내고 새 종류를 소환한다. 마지막 한 종류를 제거하지 않는다.

소환 한 종류만 배운 경우 기존처럼 최대 3개체를 허용한다. 새로운 스탯·피해·HP·지속 시간 배율은 추가하지 않는다. 실제 캐스트 주기에 기존 풀/카운터를 사용하며, 마왕 모드의 소환 AI와 슬롯 성장은 유지한다. 이전 문서의 용사 모드 고정 3체 제한보다 이 정책이 우선한다. 4종 동시 운용의 실전 승률은 별도 검증 대상이다.
