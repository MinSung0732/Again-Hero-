# 별도 프로필 화면

기타 → 프로필은 기존 로비 상단 재화·하단 메뉴 사이의 독립 서브화면이다. 기존 금색/보라색 프레임·Galmuri 폰트를 재사용하며 본문만 내부 스크롤한다. 기타 재선택·뒤로가기는 대분류 목록으로 돌아간다. 설정의 계정 연결/로그인/클라우드/쿠폰은 그대로 유지한다.

## 표시와 저장의 의미

| 항목 | 의미 | 저장 |
| --- | --- | --- |
| 닉네임·성별 | 기존 canonical 계정 정체성 | 기존 `player_profile.value`; 이 화면에서 수정하지 않음 |
| 초상화 | 프로필 카드의 작은 얼굴 이미지; 설정 계정 카드도 동일 선택 표시 | `stage_progress.cfg`의 `profile_cosmetics.avatar_id` |
| 배너 | 프로필 카드의 큰 일러스트 | 같은 섹션의 `banner_id` |
| 대표 캐릭터 | 기존 마왕 외형 선택 및 이후 대사 이미지 | 기존 `demon_appearance.equipped_id` 재사용 |
| 칭호·랭킹 | 기능 미구현 | 준비 중 표시만; 수치·보유 상태·저장 필드 없음 |

초상화/배너를 아직 따로 선택하지 않은 기존 저장은 대표 외형을 따른다. 대표 외형도 없으면 기존 계정 성별 기본값을 따른다. 한 번 따로 선택하면 해당 슬롯만 바뀌고 대표 외형/다른 슬롯/정체성/재화는 보존된다. 유효하지 않은 ID는 읽을 때 기본값으로 표시하고 새 저장은 거부한다. 현재 실제 선택지는 기존 무료 기본 남녀 2종뿐이다.

기존 AccountSaveScope를 통해 게스트·계정 범위를 분리하고 stage_progress의 다른 섹션을 보존한다. 기존 snapshot 전송 대상으로 포함된다. 서버 스키마/RPC/유료 스킨 인가 변경은 없다. 로컬 파일이나 snapshot으로 미래 유료 스킨의 소유권을 인정하지 않는다. 선택창이 열린 뒤 계정 범위가 바뀌거나 저장 충돌/동기화가 진행 중이면 적용을 차단한다.

## 에셋과 확장

`profile_cosmetic_catalog.gd`는 슬롯/버튼/기본 배너 경로를 보관한다. 제공된 남녀 배너는 원본 바이트 그대로 `assets/art/UI/profile_v1/`에 저장하고 기존 초상화를 사용한다. UI 기능 아이콘 5개는 문자 없는 새 SVG이며 제작 출처는 인접 SOURCE.md에 기록한다. 배너를 로비 로딩에서 예열하고 화면의 텍스처/컨트롤/선택창은 유지해 재진입 때 이미지 처리·새 GPU 텍스처 생성을 반복하지 않는다.

일러스트 감상은 선택 배너를 사용하는 준비 중 비활성 가로 버튼이다. 그 아래 182px 공간은 후속 기능용으로 비워두며 컷신 버튼/문구/동작은 없다. 칭호/랭킹/일러스트 보유 목록은 실제 기능이 연결될 때 구현한다.

## 검증

`tests/lobby_profile_smoke.gd`: 슬롯 독립 저장·정체성/재화 보존·남녀 legacy 기본값·계정 snapshot 왕복·범위 변경 후 오저장 방지·실제 버튼 클릭/드래그 취소·내부 스크롤/하단 메뉴 비침범·준비 상태·빈 공간·캐시 재사용 검사. `--capture` 실행은 남녀/선택창/하단 실제 렌더를 outputs에 기록한다.

2026-10-06 Godot 4.7.2 headless 및 Windows OpenGL 격리 실행/캡처 확인. 설정·기존 외형 회귀 검사 포함. Android 실기기 터치와 실제 계정 간 클라우드 동기화는 별도 QA가 필요하다. 기존 commerce 프레임 raw PNG export 경고와 샌드박스 인증서 저장소 읽기 오류는 이 UI 변경과 별개의 기존/환경 제약이다.
