# 「용사, 또 너야?」 캐릭터 픽셀아트 공식 규격

이 문서는 앞으로 제작하거나 수정하는 모든 플레이어블/적대 캐릭터의 인게임 도트와 초상화에 공통 적용한다. 캐릭터별 디자인 설정은 각 작업 지시가 우선하며, 아래 기준은 그림체와 리소스 규격을 통일하기 위한 것이다.

## 공식 스타일 레퍼런스

- 인게임 동작/SD 비율/실루엣/픽셀 밀도: `res://assets/art/heroes/stage8_summoner/stage8_hero_spritesheet.png`
- 얼굴/명암/외곽선/초상화 구도: `res://assets/art/heroes/stage8_summoner/8stage_hero_portrait.png`
- 화면상 캐릭터 체급: Stage 1 견습 마도사 및 `HERO_RESOURCE_STANDARD.txt`

Stage 8 파일은 디자인 복제 대상이 아니다. 새 캐릭터의 머리, 얼굴, 의상, 무기, 직업 장비와 색은 해당 캐릭터 설정을 따른다. 두 파일은 픽셀 밀도, 얼굴 비율, 3단계 명암, 색 있는 외곽선, SD 비율, 초상화 점유율을 맞추는 스타일 레퍼런스로만 사용한다. 원본 파일 크기는 각각 1448×1086, 1254×1254이므로 최종 32×32/64×64 납품 치수의 예시로 해석하거나 단순 축소하지 않는다.

## 공통 그림체

- 모바일 2D RPG에서 바로 사용할 수 있는 실제 게임 리소스로 제작한다.
- 귀엽지만 너무 유아적이지 않은 SD 애니메이션 RPG 스타일, 약 2~2.1등신을 사용한다.
- 픽셀 단위가 선명해야 하며 머리, 눈, 얼굴은 현재 게임 캐릭터처럼 또렷하게 읽혀야 한다.
- 장비와 직업은 작은 화면에서도 실루엣만으로 구분되어야 한다.
- 금속, 천, 가죽은 픽셀 명암으로 간결하게 표현하고 과도한 일러스트풍 세부 묘사는 피한다.
- 안티앨리어싱, 블러, bilinear interpolation, 반투명 외곽선을 금지한다.
- 배경은 완전 투명 PNG로 제공한다.
- 이미지 안에 텍스트, 프레임 번호, UI, 그리드, 셀 테두리를 넣지 않는다.

## 색과 명암

- 색은 선명하게 쓰되 지나치게 높은 채도는 피한다.
- 기본색, 그림자, 하이라이트 중심의 3단계 명암을 기본으로 한다.
- 광원은 좌측 상단으로 통일한다.
- 외곽선은 완전 검정 일색을 피하고 소재와 색에 맞는 짙은 남색, 갈색, 회색 계열을 사용한다.
- 금속 장식은 금색 또는 은색 하이라이트를 명확히 표시한다.

## 32×32 캐릭터 스프라이트

- 실제 캐릭터 본체 도트의 기준 영역은 32×32이며 화면상 체급은 Stage 1 견습 마도사와 통일한다.
- 기본 방향은 오른쪽을 바라보는 사이드뷰다.
- 모든 프레임에서 몸통 중심 X좌표와 발바닥 Y좌표를 고정한다.
- 머리, 몸통, 무기의 기본 크기가 프레임마다 흔들리거나 변하지 않게 한다.
- 가장 큰 동작을 기준으로 셀 캔버스를 정한다. 작은 동작 프레임을 셀에 맞추려고 확대하지 않는다.
- 공격 이펙트나 긴 무기로 32×32를 넘는 경우 캐릭터 본체 비율은 유지하고 셀만 넓힌다.
- 같은 애니메이션은 동일 셀 크기와 anchor를 사용하며 프레임 사이에 충분한 완전 투명 간격을 둔다.
- Sprite Sheet에서는 같은 애니메이션을 같은 행에 순서대로 배치하고, 행 사이도 자동 분리가 가능하도록 충분히 띄운다.
- 확대/축소가 필요하면 nearest-neighbor만 사용한다.

## 기본 모션

- `idle`: 4프레임, loop. 마지막 프레임에서 첫 프레임으로 자연스럽게 이어져야 한다.
- `walk`: 6프레임, loop. 마지막 프레임에서 첫 프레임으로 자연스럽게 이어져야 한다.
- `attack`: 6프레임, one-shot.
- `hit`: 3프레임, one-shot.
- `death`: 4프레임, one-shot.
- 캐릭터 역할상 필요하면 `run`, `cast`, `summon`, `special`로 일부 모션을 교체하거나 추가할 수 있다. 교체 내역과 프레임 수는 manifest에 명시한다.

## 64×64 초상화

- 최종 출력은 실제 64×64 픽셀아트 PNG다.
- 상반신까지만 표현하고 얼굴을 화면 중심에 둔다. 머리와 어깨가 충분히 보여야 한다.
- 전신 구도와 과도하게 확대한 얼굴 구도를 금지한다.
- 캐릭터 고유 머리, 눈, 의상, 장비, 색상을 유지한다.
- 현재 게임의 마법사, 도적, 총잡이, 연금술사, 성직자 초상화와 비슷한 픽셀 밀도를 사용한다.
- 고해상도 애니풍 일러스트를 축소한 결과가 아니라 처음부터 64×64 도트로 제작한 형태여야 한다.
- 배경은 완전 투명 PNG다.

## 납품 구조

가능하면 아래 묶음을 모두 제공한다.

```text
character_name/
├─ character_name_spritesheet.png
├─ character_name_portrait.png
├─ frames/
│  ├─ idle_01.png ... idle_04.png
│  ├─ walk_01.png ... walk_06.png
│  ├─ attack_01.png ... attack_06.png
│  ├─ hit_01.png ... hit_03.png
│  └─ death_01.png ... death_04.png
├─ manifest.json
└─ character_name_pixel_assets.zip
```

- 개별 프레임 이름은 `idle_01.png`, `walk_01.png`, `attack_01.png`, `hit_01.png`, `death_01.png` 형식을 사용한다.
- ZIP에는 Sprite Sheet, 64×64 초상화, 개별 프레임, manifest를 포함한다.
- `manifest.json`에는 캐릭터 ID, 방향, 프레임별 파일 목록, FPS, loop 여부, 셀 크기, 몸통 중심 X, 발바닥 Y, 초상화 파일을 기록한다.

예시 스키마:

```json
{
  "character_id": "example_hero",
  "direction": "right",
  "cell_size": [48, 48],
  "body_pixel_target": [32, 32],
  "anchor": {"center_x": 24, "foot_y": 42},
  "portrait": "example_hero_portrait.png",
  "animations": {
    "idle": {"fps": 6, "loop": true, "frames": ["frames/idle_01.png"]}
  }
}
```

실제 프레임 목록은 모두 기록하며, 위 숫자는 필드 형태를 보여주는 예시일 뿐 캐릭터별 확정 좌표가 아니다.

## 최종 검수

- PNG가 RGBA이며 배경 alpha가 완전 투명인지 확인한다.
- 반투명 외곽선, 보간 픽셀, 블러, 셀 테두리, 텍스트가 없는지 확인한다.
- 모든 프레임의 몸통 중심 X, 발바닥 Y, 머리/몸통/무기 기본 크기를 비교한다.
- 반복 모션의 마지막→첫 프레임 연결을 확인한다.
- Sprite Sheet와 개별 프레임의 픽셀이 일치하는지 확인한다.
- Stage 1 견습 마도사와 실제 화면상 체급을 비교한다.
- 64×64 초상화가 상반신 구도와 고유 디자인을 유지하는지 확인한다.
- manifest의 프레임 수, 파일 경로, 셀/anchor 정보와 실제 파일을 대조한다.
