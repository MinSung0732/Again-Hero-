# 이자나미 전투 소환 예시

Godot `src/dev/IzanamiBattleSummonPreview.tscn` 열고 F6. 자동 재생 후 소환 재생 / 중단·복귀 버튼 사용. 격자 배경과 실제 idle 도트 소환체는 확인용 sandbox이며 실제 몬스터 스탯/스킬/소환조건이나 계정 저장이 없습니다.

5초: 삼각형 우하단 신사 배경에 눈감은 기도 모습부터 표시 → 머리카락/옷 미세 바람과 손 충전 →2.15초 맥동·실제 소환체 중심 부적 고리/6영혼불/파문 → 일러 얼굴 집중에서 원래 구도로 돌아오며4초 이름 →5초 카메라/게임 속도/조명 복귀.

카메라 집중1.25배, 최소속도 기존속도×0.22, 접근1초, 속도 복귀3.0~3.6초. 기존 Controller가 원래 위치/줌/카메라/속도를 보관하고 모든 중단 경로에서 복구합니다. 캐릭터 이동·전투판정·소환 자원 변경 없음. 부적/불/파문은 전용 PNG atlas를 사용한 시각효과이며 별도피해 없음. 기존 Pixabay 충전0.5초/-18dB, 방출2.15초/-12dB. 취소/완료 시 양쪽 정리.

11파츠 원본 기반 연속 메시 리깅 재사용. 눈감음은 원본 상태이며 눈뜨기/팔 펼침 미구현. 큰 관절 동작은 가림부와 눈/입 파츠 보완 필요. 배경만 삼각형으로 제한, 일러는 삼각형 밖으로 펼치되 전투 패널 바깥에서 제한. 마지막 구도에서 오른쪽 옷끝 여백 확보.

실제 이자나미는 여전히 몬스터/뽑기/전투 Catalog 미등록입니다. 예시 Catalog `prewarm=false`라 현재 일반 전투에서 해당 리소스를 예열하지 않습니다. 전투 등록 후 같은 transcendent_summoned 신호를 보내면 연출 경로를 재사용할 수 있습니다. 기존 제우스/불가살 기본 예열은 유지.

검사: `godot --headless --path . --script tests/izanami_battle_summon_smoke.gd`. 실제 production Controller로 신호·3비율·카메라/속도 정확복귀·대상좌표불변·메뉴/증강/HP0/패널숨김/직접취소·음원정리·캐시 노드재사용을 검사. Linux OpenGL 렌더 확인. 기존 종료1리소스 경고 잔존; 전체 게임/Android/청감 미검증.
