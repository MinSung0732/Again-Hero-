# 메인 던전 도구 영역

- 도전과제·이벤트·탐색보상은 왼쪽, 친구목록은 오른쪽. 도전과제·이벤트·친구목록은 준비 중 안내, 탐색보상은 실제 수령 화면을 표시한다.
- `src/data/lobby_tool_catalog.gd`의 ENTRIES에 고유 id, title, side(left/right), icon 경로를 추가한다. 배열 순서가 표시 순서다. 이벤트는 left, 길드 등 커뮤니티는 right.
- 실제 화면이 생기면 `main_tools_view.register_action(&"daily", open_daily_screen)`처럼 Callable을 등록한다. 도구 뷰를 수정할 필요가 없다.
- 한쪽 영역은 104×108 논리 픽셀 버튼 최대 3개로 제한한다. 도구가 4개 이상이면 직접 표시 2개와 더보기 1개로 바뀐다. 1080×1920 화면에서 중앙 카드/좌우 화살표에 접근하지 않는다. 더보기는 스크롤 가능한 4열 모달이다.
- 카탈로그·버튼은 설치 시, 더보기 내용은 해당 카테고리를 처음 열 때만 만든다. 매 프레임 처리와 전체 트리 탐색이 없다. 텍스처는 도구 영역 안에서 캐시한다.
- 튜토리얼/전투 입장 중 열기 방지, 터치가 도구에 들어오면 던전 스와이프 시작 방지, 메인 탭 숨김 시 팝업 닫기.
- 검증: Godot 4.5.1 독립 프로젝트에서 `--headless --script docs/tests/lobby_tool_trays_check.gd`. 실제 게임 프로젝트는 전체 에셋/자동로드가 필요하다. 이번 테스트는 독립 뷰 검증이며 전체 로비/Android/iOS 시각 검증은 수행하지 않았다.

- 알림은 `main_tools_view.set_notification(&"daily", unclaimed_rewards)`로 설정한다. `daily`는 도전과제, `weekly`는 이벤트의 기존 안정 ID이며 이름 변경 때문에 저장/콜백 ID를 바꾸지 않는다. 실제 완료 조건/보상 기능이 추가되면 상태 변경 시 호출한다. 현재 완료 데이터는 없으므로 이 두 도구에 가짜 빨간점은 표시하지 않는다. 탐색보상은 300% 시 자동 표시하고 수령 직후 해제한다.
