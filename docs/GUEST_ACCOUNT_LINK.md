# 게스트 진행도 연동·리세마라

## 사용자 동작

- 기타 → 설정 → 계정에서 **Google 연동 / 카카오 연동 / 게스트 초기화**를 선택한다. **기존 계정 로그인**은 기존 클라우드 저장을 불러오는 별도 동작이다.
- 일반 게스트도 로컬 프로필·프롤로그·튜토리얼을 진행한다. 완료/스킵 보상1000골드는 게스트별1회 지급하고, 초기화는 새 게스트 ID와 새 진행도로 시작한다. 일반 계정 저장은 초기화하지 않는다.
- 우리 게임의 등록 기록이 있는 소셜 계정으로 연동하면 **이미 가입된 계정입니다** 안내를 띄우고 게스트 저장/로그인 상태를 유지한다. 0골드/최대1스테이지도 기존 가입자로 판정한다.
- 신규 소셜 계정에는 게스트의 진행도·재화·몬스터·편성·연구·뽑기 이력·튜토리얼 수령 기록을 함께 옮긴다. 기존 계정과 합치거나 덮어쓰지 않는다. 테스트99999 모드와 첫 가입 미리보기는 연동 대상에서 제외한다.
- 게스트 닉네임이 서버에서 이미 사용 중이면 진행도를 보존하여 이전하고, 새 계정 진입 때 프로필 이름을 다시 설정한다. 기존 계정의 닉네임을 빼앗지 않는다.

## 저장 및 실패 경계

게스트 ID는 stage_progress.cfg의 guest_identity에 저장하며 디렉터리별로 캐시한다. OAuth 검증 직후 원래 게스트 ID/디렉터리를 재확인하고 최신 파일을 캡처한다. 소셜 토큰을 별도 RPC에 전달하되 게스트 저장 소유자는 서버 승인 전까지 변경하지 않는다. 실패/계정 충돌 시 정상 클라우드 초기화를 호출하지 않고 게스트를 유지한다. 로그인/초기화/다른 게스트로 전환하면 오래된 응답을 적용하지 않는다.

`account_private.registrations`는 공개 API에서 직접 읽거나 쓰지 못하며 RLS와 권한 회수를 적용한다. 배포 전 auth 사용자 모두를 기존 가입자로 기록한다. 이후 정상 read_game_save와 게스트 이전은 같은 auth 사용자 PK 잠금을 사용한다. 서버 이전 RPC는 JWT의 사용자와 살아 있는 세션만 받으며 caller user_id 파라미터는 없다. guest ID의 UNIQUE 제약으로 같은 진행도를 여러 계정에 복제하지 못한다.

이전은 등록·스냅샷·프로필·튜토리얼 기록이 한 트랜잭션에서 반영된다. 동일 사용자+게스트ID 재시도는 저장을 다시 쓰지 않고 서버 최신 스냅샷을 반환한다. 타임아웃이나 기기 기록 실패 시 같은 소셜 계정으로 재시도할 수 있다. 기기 저장까지 성공하면 guest_claim.cfg로 이전 완료를 기록하고, 이후 게스트 로그인은 새 진행도를 시작한다. 원본 게스트 파일은 성공 전 지우지 않는다.

서버는 기존 튜토리얼 보상 수령 여부를 이전하므로 다시1000골드를 지급하지 않는다. 이 기능은 기존 클라이언트 스냅샷 저장 구조를 사용한다. 수정된 클라이언트가 로컬 재화/아이템을 조작하는 문제 전체를 해결하는 서버 경제 검증 시스템은 아니다. 출시 전 서버 경제 검증은 별도 범위다.

## 적용·검증

- Supabase CLI migration new로 생성한 뒤 적용된 서버 이력 버전에 맞춘 `20261012035726_guest_account_link.sql`. 서버 적용 및 migration list 확인 완료. 기존 사용자 저장/탈퇴 데이터는 변경하지 않았다. 신규 등록 판정 테이블만 기존 auth 사용자 ID로 채웠다.
- SQL 트랜잭션/ROLLBACK fixture13검사, 배포 후 동일13검사 PASS. 기존0계정 보호, 신규 이전, 몬스터/수령 기록, 재시도 무덮어쓰기, 다른 소셜 중복 이전 금지, 정상 로그인 우선, 잘못된 저장/세션 거부, anon 및 직접테이블 권한 차단.
- Godot4.5.1 격리 실제 소스+fake OAuth/RPC: guest_link_smoke28, 이전 account_transition33, guest_profile_flow10, 실제 게스트UI8, 기존 dungeon_entry_notice36 검사 PASS. 기존 cloud_save_smoke PASS. 원본 도트 프레임/Galmuri11로 가입 계정 안내 렌더 확인. UI host/비관련 몬스터 씬만 fixture 대체.

- 로컬 Postgres/Docker가 없어 db pull/list --local은 수행 실패. hosted migration list·실제 RPC/권한 쿼리로 검증했다. Security advisor의 private registrations RLS 정책 없음 INFO는 직접 접근을 금지한 의도된 상태이며, 기존 leaked-password WARN은 이번 패치에서 변경하지 않았다.

탈퇴30일 보관·동일 계정 재가입 차단 정책은 이번 게스트 연동 패치에 포함되지 않는다. 이전 손실 데이터 복구도 수행하지 않았다.

## 롤백

클라이언트는 이 패치 커밋을 revert할 수 있다. 이미 이전한 스냅샷·프로필·보상 기록·등록 이력은 삭제하지 않는다. 서버 이전 중단이 필요하면 public.link_guest_save와 account_private.link_guest_save의 authenticated 실행 권한을 회수하고 구버전 read_game_save 정의를 복원한다. registrations는 감사/중복 이전 방지를 위해 보존한다.
